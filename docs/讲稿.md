## 一、开场：先说说原来那个网站长什么样

大家好，我这次做的是《可视化导论》课程网站的学习体验改造。

在讲我改了什么之前，先说清楚**原来的网站是什么样的**。

它是能用的——五章内容都在，每章都有讲解、关键代码、演示三个标签页，各种交互 demo 也都能跑。但它有一个很明显的毛病：**它是从文档里"导出"出来的，不是为"上课"设计的。**

我给你看几个数。

比如第 2 章的页面，打开源代码是 **884 行**，光 HTML 就占掉这么多。这里面有 **439 处** `data-page-node-id`——这是当年从某个网页编辑器里带出来的节点编号，对这门课一点用都没有，纯粹是噪音。还有 **242 处** `data-lang` 标记，意思是每一句中文都配了一份一模一样的英文 DOM 挂在旁边。

四章加起来：**2617 行 HTML，1065 处废编号，798 份重复的中英文副本。**

所以你打开那个页面看到的是什么呢？一条长长的、找不到自己在哪儿的讲义。内容是够的，但它只适合"读"，不适合"学"。

而老师想改一句话的代价是：在两处重复的 DOM 里各改一遍。

我这次做的事，用一句话说就是：**把一个"能讲完的讲义"，改成一个"能学完的课"。**

## 二、我做了四件事

### 第一件：给网站定了一套"好看"的规矩

原来的页面是白底黑字、宋体、没有任何层次——你滚动的时候眼睛没有落点。

我重做了一遍视觉：

- **颜色**：米黄色的纸做底，卡片是纯白，正文用接近黑的深灰，重点标注用橙色，代码区是深色
- **字体**：标题用衬线体（像书），正文用无衬线体（像屏幕），代码用等宽字体——**靠字体的粗细和明暗来分层**，不靠线和色块
- **首页**：从"一列章节列表"改成**错位卡片墙**。五张卡片高低不齐地摆着，鼠标移上去卡片会浮起来、封面会放大一点，底下还会冒出课程名、课时、难度
- **多了一条学习路径**：几个节点用虚线连起来，点一下就展开详情，告诉学生该按什么顺序学

> 📱 **演示**：首页慢慢往下滚 → 鼠标停在第二张卡上 → 点下面的路径节点

### 第二件：把五章做成同一种结构

这件事可能听起来很技术，但它解决的是一个很实际的问题：**原来每一章都是一个独立的大文件，想给某一章加个新功能，得单独改一遍。**

现在每一章被拆成四个小文件，各管一件事：

```
lesson-0X/
├── index.html    只有 22 行，就负责引一下样式和脚本
├── content.js    这一章讲什么（中英文都存这儿）
├── demos.js      这一章的交互演示
└── main.js       入口，把上面几样组装起来
```

**最后 22 行这个数字，是我最想让大家看到的。** 内容再长也不要紧，因为它不在 HTML 里了。

好处很直接：以后加一节课，只改 `content.js`；改一个按钮的样式，五章一起变，不用挨个改。

顺便还清了一堆历史包袱：每个章节目录下遗留的旧样式文件、旧脚本、中英文块 JSON 翻译产物，都删掉了。**课程页面的 D3 库也从网上引改成放在本地了**（273 KB），所以教室断网也能正常上课。

### 第三件：给每一节配上"学完的证据"

这是我觉得对一个学生最有用的一块。

原来你读完一节，只能凭感觉说"我好像懂了"。现在每一节都有三样东西：

- 🎯 **开头写清楚这节要会什么**（3 条，就摆在那儿）
- 📌 **结尾一段小结**，把这节的要点收回来
- 🧪 **结尾几道小测验**，点一下选项立刻告诉你对错，并且**告诉你为什么**

另外整章的左边目录也能用：

- 每节前面有个**小勾选框**，学完打勾
- 上方有**进度条**，显示这章学了多少
- 往下滚动的时候，目录会**自动高亮**你正在看的那一节
- 代码块右上角有**复制按钮**，一键拿走

这些全部记在浏览器本地，关掉网页再回来也还在。

**算下来的覆盖情况**：27 节**全部**都有目标和小结，34 道自测题，58 个代码块都能复制，27 个交互演示。**一节都不落。**

> 📱 **演示**：进任意一章 → 左边勾几个小节（看进度条和圆环动起来）→ 切到"关键代码"标签 → 点复制 → 滚到底答一道题

### 第四件：加了两个我觉得还挺有意思的功能

#### 功能 A：五格圆环 + 学完撒彩带

**我为什么想做这个？** 因为一个五章的课，学生永远不知道自己走到哪了、还剩多少。学完的感觉应该是有的，但原来没有地方体现。

所以我在左边目录最下面放了一个**被分成五格的圆环**，每一格代表一章：

```
橙 → 赭 → 绿 → 蓝 → 梅
```

某一章的小节**全部勾完**，那一格就点亮成它自己的颜色。没点亮的时候是接近纸色的白。圆圈中间显示"你已经学完几章"，下面还有五颗小点跟着一起亮。

**五章全部点亮的那一刻**，屏幕上会**撒一次彩带**（大概 6 秒），然后下面出现一行字：**"恭喜学完本课程"**。

彩带只撒一次，不会每次进来都闹你；旁边有个"重置进度"，老师想重新演示可以点一下。

> 圆环的颜色是一章一个的，不是随便挑的——是从我们的主色系里排出来的，橙、赭、绿、蓝、梅，深浅也有讲究。

#### 功能 B：右边一个能贴截图的笔记本

**这个功能是我自己想用的。** 上课听到一个想法，当时不记下来，课间就忘了；下次回来，草稿也不在了。课件末尾那行"最后一句话"，留不住任何东西。

所以我在页面右边放了一个笔记本，**五章共用同一个**——你在第 3 章记的，切到第 5 章还在。

- 打字就自动存，不用点保存
- 可以**附图片**：点"＋ 附图片"选一张，或者**直接 Ctrl+V 粘贴截图**（截图工具截完直接贴进来就行）
- 图片排成小方块，点一下能放大看，右上角可以删
- 右边边缘有个竖着写的"笔记"把手，点一下展开、再点收起；宽屏下正文会往左让一让，不会被挡住

**这里有个技术上的小讲究**，我想说一下：文字和图片是**分开存**的。浏览器给普通存储的空间只有 5MB，而一张截图就几百 KB，塞几张就满了。所以文字走普通存储，图片走浏览器另一个容量大得多的专门空间。贴图之前还会先自动压一下，一张截图能压到 100KB 左右，能存很久。

还有一点：**剪贴板里只有文字的时候，我是不会拦截粘贴的**。不然你从 PDF 里复制一段文字想贴到笔记里，也会莫名其妙失效。

> 📱 **演示**：Ctrl+V 贴一张截图 → 切到第 5 章 → 内容还在 → 点缩略图放大

## 三、额外做了一个：能一行一行跑的"互动课"

除了改造原来那五章，我还做了一套**全新的互动课**（12 节），在 `lesson.html`。

它最特别的地方是：**代码可以一行一行地跑。**

学生点"下一步"，代码就执行一行，右边实时显示每个变量是什么类型、什么值——数组还会用小方块画出来，变量一变就闪一下提醒你，console.log 的输出也会一条条冒出来。像循环这种会重复跑很多遍的代码，只在头两轮停下来让你看，之后就让它跑完。

**为什么做这个？** 因为"看懂代码"和"看着代码一行行跑出来"，是完全不同的两种体验。

举个例子：讲双层数据聚合的时候，学生不用背"先按专业分、再按班级分"，他可以**眼睁睁看着那个嵌套对象从空的一步步长出结构来**。这个理解是跑出来的，不是背出来的。

每节课还配了**自动判分的练习**（一共 39 项检查）和小测验。

## 四、过程中踩的坑（这部分我挺想讲）

做这个项目最有意思的不是加功能，而是**跟一堆 bug 打架**。挑五个我觉得有代表性的：

**① 第 5 章热图上的提示糊成一片黑**

鼠标扫过热图，整个图上堆满了黑色小标签。查下来是：代码里把提示标签**挂到了页面最外层**，但要删它的时候却**跑到组件内部去找**——那当然找不到。于是每扫过一个格子就多一个标签，旧的还删不掉。改成"全章共用一个标签，用显示/隐藏来控制"就好了。

**② 温度全是 0 度**

同一个图，温度显示 `0.0°C`。原因是读取 CSV 时我开了个"自动识别类型"的功能，它把日期那一列变成了日期对象，可我查表用的还是字符串——**类型对不上，永远查不到**，所以全成了 0。关掉这个功能让日期保持字符串就好了。修完之后 366 天的数据全部命中，温度范围是 −4.0 ~ 22.6 度。

**③ 进度条显示 "27 / 5"**

分子数的是全部五章学完的节数，分母只有这一章的节数。改成分子分母都只算**这一章**。

**④ 圆环画不出来，还多了一个奇怪的 `>` 字符**

我把一个"中英文双份"的小组件塞进了提示文字（`aria-label`）里，而那个组件自己带着双引号——**双引号把属性提前关掉了**，整个 SVG 就被浏览器解析坏了。改法很简单：放提示文字的位置不能用这种组件，要用纯文字。

**⑤ 首页进度一直是 0%，但章节页明明是 100%**

这个最有意思。查下来是**两个地方用了两个不同的"记账本"**：章节页记在一个名字下，首页记在另一个名字下，各记各的，谁也看不到谁。统一到同一个本子之后，两边数字就完全一致了。

> 这五个 bug 有个共同点：**光看代码是看不出来的**，得真的把它跑起来、拿鼠标点。所以我最后干脆老老实实做了个能自动检查的小工具，每个改动都跑一遍验证。

## 六、结尾

最后想说一下我自己对这件事的看法。

原版网站的内容是**够的**，五章、几十个知识点、二十多个交互演示，该有的都有。我做的事情其实都指向同一个目的：**给学习的过程加上"反馈"和"痕迹"。**

- 反馈：让你知道这节要会什么、答得对不对、现在学到哪、还剩多少
- 痕迹：让你想到的、看到的、拍下来的，不会因为关掉网页就没了

教学网站的价值，我觉得不在"内容多"，而在**"学生能不能真的走完"**。走完的人会记住这个课，走不完的人连门都懒得进。

也想说一下我知道还差什么：

1. 右边那个笔记本，现在只装在五章教学页上，新做的那套互动课还没接上（数据层是通用的，接很快）
2. `lesson-01/demo/` 下面几个独立的小 demo 还是从网上引 D3，和"零依赖"的说法不一致，这是改之前就有的问题，我没动
3. 章节清单里每章有多少节，这个数是手动维护的，以后加节减节要记得两边一起改

我的汇报就到这里，谢谢大家，请老师指正。
