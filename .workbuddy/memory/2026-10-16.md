**逐步执行引擎的关键实现点（踩过的坑）**
1. `new Function("__scope", "__mark", "return (async function(){ with(__scope){...} })();")` —— 参数名必须与 with 里的标识符完全一致，否则 ReferenceError
2. Proxy 的 `has()` 必须对所有标识符返回 `true`，否则未声明变量的赋值会逃逸成全局变量，变量面板什么都捕获不到
3. `with(__scope)` 会把 `__scope`、`__mark` 自身也送进 Proxy，必须预先播种到 scope 对象
4. 插桩方式：每行前插 `await __mark(n);`（放在行首而不是行尾，才能安全处理纯注释行和 `} else {` 这类行）
5. 循环体每轮迭代都会重新触发 mark，一个 371 次的日历循环会 mark 1502 次 → 给每行的暂停次数加上限（前两轮暂停），且超过上限的行完全跳过 DOM 工作
6. 课程代码书写约定：每行一条完整语句、函数定义写在一行、不用解构声明、注释可写在行尾（插桩时剥离）

**数据校验方法**（无 puppeteer 时的替代方案）
用 Node vm + 复刻沙箱语义（Proxy + with + new Function）跑参考解，验证 39 项 checks 期望值 + 12 节示例代码可执行 + 全量步进可走到结束哨兵。三个临时脚本已删除，需要时可从 git history 或本笔记复现。

**现象**：点「进入这一章」后只有顶栏，下面全空白。

**根因**：lesson.html 的所有区块都带 `.reveal` 类（`opacity:0` + `translateY`），而驱动它的 IntersectionObserver 只写在 home.js 里，课程页没加载 home.js → 这些元素永远不加 `.in`。

**教训**：动态插入的内容若带 scroll-reveal 类，必须在插入后再 observe；这类"只在 JS 里加 class"的样式，DOM 桩测试（只查 children/textContent）查不出来，必须单独验证 class 是否被加上。

## 修复：仪表板圆环不显示

**现象**：仪表板标题、百分比、「恭喜学完本课程」都正常，但圆环位置一片空白，还多出一个游离的 `>` 字符。

**根因**：`aria-label="${bi("五章学习进度环", "Five-chapter progress ring")}"`。
`bi()` 返回的是 **HTML**（`<span data-lang="zh-CN">…</span><span data-lang="en-US">…</span>`），
其中 `data-lang="zh-CN"` 的双引号把 `aria-label` 属性提前闭合，浏览器解析器随即把剩余内容当标签外文本，
整个 `<svg>` 被撑坏 → 圆环画不出来 + 出现游离的 `>`。

**修法**：属性值里改用 `T()`（返回纯文本），只保留 `bi()` 用在元素内容位置。
同时给五段加了一层 `.dash-track` 底圈，未点亮时圆环形状仍可辨。

**教训（重要）**：
1. `bi()` 永远不能进属性值（`title=`、`aria-label=`、`alt=` 同理），只能进元素内容。
2. **正则/字符串级的 HTML 检查查不出这类 bug** —— 上一轮的验证用正则数 `<circle>` 个数，
   因为源码字符串本身是完好的，所以「通过」了；只有真正的 HTML 解析器才会暴露问题。
   后来补的良构性检查专门看「属性值里是否混入 `<`/`>`」「标签是否配对」，才拦住这类问题。
3. 检查规则本身也会有假阳性：正文里的裸 `>`（如 `点数 > 500`、`duration>1500`）是合法文本，
   不能用「去标签后找 `>`」这种朴素规则。

## 修复：lesson-05 两个演示的提示堆叠与数据失效

用户截图反馈 5.3 日历热图、5.4 螺旋日历的 hover 提示糊成一片黑块，且温度显示为空。

### Bug 1：提示元素作用域错配（提示堆叠成灾）
`showTip` 里 `document.body.appendChild(tip)`，但 `hideTip` 里用 `mount.querySelector(".ts-tip")` 去 **mount 内部**找。
tip 在 body 下、却在 mount 里找 → 永远返回 null，于是：
1. `showTip` 每次都认为「tip 不存在」→ 每 hover 一次新建一个
2. `hideTip` 找不到任何东西 → 旧的永远删不掉
鼠标扫过热图（366 个格子）就堆出几百个黑块。
**修法**：抽成模块级共享提示层，全章一个 `.ts-tip` 元素，用 `hidden` 开关而不是 `remove()`；
`position: fixed` + `transform` 定位（clientX/Y 直接可用），并夹在视口内防贴边溢出；样式从行内 cssText 挪进 demo.css。

### Bug 2：`d3.autoType` 导致日期键类型不匹配（温度全变 0）
`d3.csv(url, d3.autoType)` 会把 `date` 列转成 **Date 对象**，
而查询用的是 `d3.timeFormat('%Y-%m-%d')(d)` 产生的 **字符串** → Map 永远查不到 → 全部退化成 0。
**修法**：去掉 `autoType`，让 date 保持 CSV 原始字符串，`temp_max` 用 `Number()` 转换。

### 顺手修的两处数据不一致
- 色域写死 `[30, -5]`，但 2024 北京实际只有 **-4.0 ~ 22.6°C** → 最热的格子到不了深红，图例还标着 30°C。改为从 `d3.extent` 推导，图例文案同步。
- d-5-4 用 `offset` 偏移日期，把 1 月开头几天挤出螺旋；`dayCount = 366` 还是写死的。改为按日期范围算出天数，周起点只用来旋转起始角。

### 教训
- **「创建在 A、查找在 B」是提示/浮层类 bug 的经典成因**，写全局节点时查询范围必须一致。
- `d3.autoType` 会改变列的类型，做「字符串键 → 值」的 Map 查表时不能用它。
- 写死的数据范围（色域 domain、刻度上下限）很容易和真实数据脱节，应该从 extent 推导。

### 验证
用真实 D3 跑一遍数据管道：366 天全部命中、0 个 NaN、色域两端能到深红/深蓝、图例文案与数据一致。
另做代码层核查（排除注释行后）：作用域错配查询、行内 cssText、autoType、写死天数、写死色域、remove() 全部已消除。

## 修复：首页进度环恒为 0% + 侧栏进度越界 + 难度标签竖排

**现象**：用户在章节页勾选了小节、仪表板显示 100%，但首页 5 张卡片仍全是 0%。

**根因**：两套互不相通的进度键。
- 章节页（`shared/render.js`）写 `wbl-lesson-progress`（小节 id 数组，如 `ch-3-1`）
- 首页（`home.js`）读 `warm-progress-v1`（新版互动课的 lesson 状态，如 `c1-1`）

两边各记各的，首页永远读不到章节页的进度。

**修法**
1. `shared/course.js` 改成**经典脚本**（挂 `window.COURSE` / `window.courseDone`），
   首页与章节页读同一份章节清单和同一个进度 key。
   为什么不用 ES module：`home.js` 是经典脚本，module 是延迟执行的，classic 先跑，
   所以共享数据必须走 `window`，否则首页拿不到。
   render.js 也随之从 `import` 改为读 `window.COURSE`（module 延迟执行，晚于 classic，安全）。
2. 首页卡片环 + 路径节点改为读 `wbl-lesson-progress`，与课程页仪表板同源同口径。

**连带修的两个缺陷**
- **侧栏进度越界**：章节页 `done.size` 统计的是**全部五章**的已完成 id，
  分母却只有本章小节数 → 在第 5 章显示「27 / 5」。
  改为分子分母都限定在「本章小节」集合内。
- **「难度」被压成竖排**：CSS `.diff span` 无差别地把所有 `span` 设成 `width:16px;height:3px` 的色条，
  文字标签也被命中 → 「难度」两字竖排折行。
  改为独立类名 `.diff-bar` / `.diff-label`。

**验证**：造一份混合进度（第 1、5 章全完，第 3 章一半），确认首页 5 张卡片与仪表板 5 段数字**逐项一致**（100/0/50/0/100），侧栏各章显示 5/5、0/4、4/8、0/5、5/5 不再越界。

**教训**：进度类数据一旦有多处写入点，必须收敛到单一数据源 + 单一 key；
另外「统计全局 / 显示局部」是最容易出现的进度条 bug，写的时候要确认分子分母口径一致。

## 新增：全局课堂笔记面板（右侧停靠 + 附图片）

用户要求：在课程页右侧加一个可附图片的笔记区，**五章全局共用**，用类似 WorkBuddy 侧栏面板的按钮展开/收起。

### 实现
- `shared/notes.js` + `shared/notes.css`，由 `shared/render.js` 在渲染后动态 `import("./notes.js")` 初始化
  （不用静态 `<script>`，因为面板要挂到 render.js 生成的 `.lesson-layout` 上，必须等它建好）
- 面板作为 `.lesson-layout` 的**第三个子节点**；展开时 body 加 `.notes-open`，
  栅格从 `250px 1fr` 变成 `250px 1fr 340px` → **内容让位而不是被遮挡**
- 窄屏（<1180px）改为右侧覆盖式抽屉 + 半透明遮罩
- 开合把手：右侧边缘竖排「笔记」标签（`.notes-toggle`），展开后滑出屏幕

### 存储选型（关键决策）
- **文字 → localStorage**（key `warm-notes-v1`），防抖 400ms 保存
- **图片 → IndexedDB**（db `warm-notes` / store `images`，存 Blob）
  理由：localStorage 只有 ~5MB，一张截图就几百 KB，很快撑爆；IndexedDB 配额大得多
- 上传前用 canvas 压缩：最长边 1400px、JPEG 0.72，一张截图通常压到 100KB 上下
- 键名与页面无关，所以五章天然共用同一份笔记；开合状态存 `warm-notes-open`
- objectURL 在重渲染与 `pagehide` 时 revoke，避免内存泄漏

### 验证
用 DOM 桩（假 IndexedDB / localStorage / canvas.toBlob）跑全流程：
面板结构完整、默认展开、文字输入落盘、把手续存状态、上传走 canvas 压缩 → 写入 IndexedDB → 画廊与计数更新，全部通过。

**踩坑**：桩的 `innerHTML` 解析一开始不递归，导致 `panel.querySelector(".notes-collapse")` 返回 null 误报。
这类「用正则/字符串模拟 DOM」的桩，只能验证一层 `querySelector`，嵌套查找必须先把结构铺平。

### Ctrl+V 粘贴
把上传逻辑抽成 `addFiles(files)`，文件选择与粘贴共用。
监听 `document` 的 `paste`，遍历 `clipboardData.items` 取 `kind === "file" && /^image\//` 的项。

**关键判断：剪贴板里没有图片时绝不 `preventDefault()`** ——
否则会把正常的文字粘贴一起拦掉（比如从 PDF/文档复制文字）。有图片才拦截，并自动展开面板 + 聚焦文本框。

面板提示文案里加了 `<kbd>Ctrl</kbd>+<kbd>V</kbd>` 说明。

### 验证

3. 面板收起时粘贴 → 自动展开、写入第 2 张 ✓
